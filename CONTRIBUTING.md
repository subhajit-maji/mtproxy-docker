# Contributing

Thank you for your interest in contributing to this project.

## Reporting Issues

If you find a bug or have a suggestion for improvement, please open a GitHub Issue and include:

- Operating system and version
- Docker version
- Steps to reproduce the issue
- Relevant log output (remove secrets and sensitive information)
- Expected behavior
- Actual behavior

## Submitting Changes

1. Fork the repository.
2. Create a new branch for your change.
3. Make your modifications.
4. Test your changes locally.
5. Commit with a clear message.
6. Open a Pull Request describing the purpose of the change.

## Coding Guidelines

- Keep scripts simple and readable.
- Prefer portable shell commands where possible.
- Document configuration changes in the appropriate Markdown files.
- Avoid introducing unnecessary dependencies.

## Security

Do **not** commit:

- `.env` files
- MTProxy secrets
- Promotion tags intended to remain private
- Private keys or certificates
- API tokens or passwords

If you discover a security issue, avoid posting sensitive details publicly. Instead, contact the repository maintainer through an appropriate private channel if one is available.

## Documentation

Contributions that improve documentation are welcome. Please ensure examples use placeholder values rather than real credentials or infrastructure details.
